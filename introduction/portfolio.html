# UX/UI 설계 디자인

포폴을 제작하는 과정에서 어떻게 나에 대해서 잘 보여줄 수 있을까에 대해서 생각해보면서 보기 편하고 간단하게 보여줄 수 있는 좋은 포트폴리오들을 참고하여 포트폴리오를 제작하였다.
좋은 포트폴리오들을 참고 후 UX/UI를 고려한 포트폴리오를 만들 수 있었다. 읽기 편한 느낌을 주기 위해 폰트는 페이북 글꼴을 사용하였다.

# 프로젝트

진행했던 팀 프로젝트를 표현하는 부분에서 여러 프로젝트를 나타내었다. 그리고 나에 대해서 표현하기 위해서 직접 작업했던 Figma와 Github를 볼 수 있는 버튼을 추가하였다. 하지만 대기업 프론트엔드 개발자분의 멘토링을 받았을 때, "양보다는 질을 중요시해라" 라는 말이 생각났다. 많은 프로젝트를 보여준다는 것은 그렇게 큰 의미가 없다는 것을 느꼈다. 그래서 프로젝트당 문제점 및 개선상황을 보여줄 수 있는 버튼을 추가하고 프로젝트를 진행하면서 생겼던 문제점과 어떻게 개선했는지에 대해 작성을 했다.

# 코드

프로젝트의 More 버튼을 클릭하면 새 탭으로 열게 하기 위해서 다음 코드를 추가하였다.

import { useNavigate } from "react-router-dom";

const navigate = useNavigate();

const firstDetail = () => {
    window.open('/MyPortfolio/firstDetail', '_blank');
};

local에서는 순조롭게 새 탭으로 열고 잘 적용이 되었다.
하지만 "build 후 실제 배포된 웹에서 상세페이지에 접속 시 404가 뜨는 가장 큰 문제가 발생했다."


HashRouter, <BrowserRouter basename={process.env.PUBLIC_URL}> 등으로 변경해보라는 말들이 많아 변경해보았지만 여전히 적용되지 않았다. public 폴더에 404.html을 추가해 리디렉션 하는 방법도 사용해 보았지만 무한 리디렉션 되는 문제점도 발생했다.


혹시나 하는 마음에 window.open 대신 navigate를 사용해보았다.

const navigate = useNavigate();

const firstDetail = () => {
    navigate("/MyPortfolio/firstDetail");
};

build 후 웹에서 상세페이지에 접속하니 거짓말같이 문제없이 렌더링 되었다. 새 탭으로 열려고 하면 window.open을 사용하는걸 권장했지만 404가 뜨는 이유로 navigate를 사용하였다.


UI를 제작했지만 너무 정적인 느낌과 사용자 관점을 좀 더 고려했다는 부분이 나타났으면 좋겠다는 느낌이 들었다. 그래서 추가한 것이 헤더의 섹션을 나누는 텍스트를 클릭할 때 자동스크롤을 추가하기로 했다. 자동스크롤을 사용할 때 js로 애니메이션을 주는게 아닌 패키지를 설치해서 사용하니 쉽고 편리하게 사용할 수 있었다.

> npm install react-scroll

react-sroll 이라는 패키지를 설치해주고


import { Link, Element } from 'react-scroll';

<ul className='headerMenuContainer'>
    <li className='headerMenuText'>
        <Link to='section1' smooth={true} duration={850} offset={-95} className='menuLink'>
            ABOUT ME
        </Link>
    </li>
</ul>

이렇게 Link를 추가해주니 쉽게 해결되었다.
